# Sprint operating standard

Cadence is one five-day engineering week with one primary outcome. Capacity assumes one
focused owner stream plus review; plan roughly 2 M tasks or 1 L task per owner. XL work must
be decomposed.

Blocked tasks are not committed unless the sprint explicitly resolves their blocker.
Carryover requires a written cause, new estimate and dependency update. Emergency P0 work
may interrupt the sprint only for data loss, authorization, safety, security or release
integrity; displaced work returns to Ready.

Review requires acceptance evidence, test output, documentation, tracker status and
percentage recalculation. A partially implemented task remains In Progress. Sprint IDs are
stable; task reassignment is historical, not destructive.
